# MaaHubCpp 代码审查报告（2026-11-27，基线 `0f4753f`）

## 一、总体评价
- **架构**：Hub（调度与计划）+ Worker 子进程（MaaCore / MaaFramework）+ 原生 GDI 界面三层分离，整体方向与 MAA「GUI ↔ Core」分层一致。
- **主要风险**：线程与子进程生命周期安全、UI 线程阻塞与 DPI 适配缺失、仓库卫生与敏感配置管理。
- **可维护性**：核心模块（`app_window.cpp` 278KB、`hub.hpp` 112KB、`maaend_adapter.hpp` 76KB）单文件偏大且大量为 header-only，后续宜按职责拆分为独立编译单元。

## 二、后端缺陷

## 三、界面缺陷

## 四、功能缺口（对照 MAA / MaaEnd）
- **对照 MAA**：外部通知渠道（Server酱/SMTP/Telegram/Bark/Webhook）、运行中改参数（`AsstSetTaskParams`）、模拟器多开与失败重启 ADB、定时器按配置切换与强制抢占、6.19-beta 新增任务（OperProgress / SwitchTheme / UserDataUpdate / DepotMaintain）、结构化掉落/公招日志卡片。
- **对照 MaaEnd / MFAAvalonia**：从 `interface.json` 动态读取 resource / controller 与嵌套选项、Agent 子进程崩溃重启、失败截图转储、多套任务配置预设。
